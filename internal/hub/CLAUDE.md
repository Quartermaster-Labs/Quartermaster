# internal/hub

## Purpose

Model browser + downloader: search a model hub from inside quartermaster, read a repo's file list, and pull a quant into the models folder, where autogen discovers it like any hand-copied GGUF. Before this, acquiring a model was entirely out-of-band (browser → manual download → drop in the folder).

Two halves, deliberately separable: a **Source adapter** (what a hub knows) and a **download Manager** (how bytes get to disk). The interface exists so a second hub — ModelScope, phase 2 — is an adapter, not a fork of the downloader.

## Key files

| File | Role |
|---|---|
| `hub.go` | Package doc, the `Source` interface, wire types (`Model`, `File`, `ModelDetail`, `Query`, `Page`), and the filename parsing every adapter shares: `classify` (quant tag, shard number, **group key**) and `IsModelFile`. |
| `hf.go` | The Hugging Face adapter. `Search` (`/api/models?filter=gguf`), `Detail` (`/api/models/{id}?blobs=true` — `blobs=true` is what makes siblings carry a size), `readme` (raw README.md), `FileURL` (`/resolve/main/…`), `CheckURL` (host pinning), `Authorize` (bearer token). Plus `hubHTTPError`/`AuthError` and the repo-id / repo-path validators. 10-minute response cache, bounded at 128 entries. |
| `header.go` | `FetchRange`/`FetchHead` — Range-fetch a window of a repo file (its GGUF header) without downloading it, so a candidate can be sized before it is committed to. Bytes only: parsing lives in `internal/server`, since this package must not depend on `internal/autogen`. |
| `download.go` | The `Manager`: job list, admission, the pause/resume/cancel verbs, and the resumable transfer (`fetchFile` retry loop → `fetchOnce` single attempt). `RepoDirName` owns the on-disk layout; `SweepPartials` clears orphaned `.part` files. |

## Important types & functions

- `Source` — `ID`/`Name`/`Search`/`Detail`/`FileURL`/`CheckURL`/`Authorize`. Implementations must be concurrency-safe.
- `Manager` (`NewManager(modelsRoot func() string, log, sources...)`) — `Start`, `Pause`, `Resume`, `Cancel`, `Jobs`, `Job`, `Source`, `Sources`. `OnComplete` is the caller's hook to regenerate + hot-reload. `launchLocked` is the shared spawn used by both `Start` and `Resume`, so a resumed job is the same job (same id, same files) rather than a new one pointed at the same repo.
- `FetchRange(ctx, src, repo, path, off, n)` / `FetchHead` (= `off 0`) / `MaxHeaderBytes` (`header.go`) — the pre-download sizing primitive. Runs the same two validators and the same **per-redirect-hop** host pinning as the download path (a `/resolve/` URL is answered by a CDN redirect), accepts a `206` **or** a `200` (a server that ignored `Range`), and reads through an `io.LimitReader` so that 200 can't turn a size probe into a 40 GB read. A short read is **not** an error: only the caller parsing the prefix can tell whether what arrived was enough, which is what lets `internal/server` extend the prefix on `io.ErrUnexpectedEOF`. **The offset is why that extension is cheap** — a caller that guessed short fetches the remainder rather than re-requesting from zero, and a real header is 6-8 MB (the tokenizer vocab dominates it), close enough to any sensible first guess that re-fetching would cost more than the header itself. `off > 0` on a `200` **discards** that many bytes before reading, since the caller is appending to a prefix it already holds and must not be handed the head of the file under a false offset.
- `Job` / `JobFile` — phase (`queued`→`checking`→`downloading`→`registering`→`done`|`error`|`canceled`, plus `paused` off to the side), byte counters, `Gated`. Copied out under the lock, never handed out by pointer (same contract as `internal/backends.Job`).
- `RepoDirName` — the on-disk layout, **`<owner>/<name>`**, mirroring the hub's own namespacing (`unsloth/Qwen3-8B-GGUF` → `…/Models/unsloth/Qwen3-8B-GGUF`) rather than the flat `owner__name` it used to emit. Every segment goes through `sanitizeSeg` **before** it is joined, and an all-dots segment (`.`, `..`) is rewritten to dashes: nesting is what turned a `..` owner into a directory climb, where the old `__` glue had made it inert. No migration — repos already on disk keep their flat folder and still load.
- `ParamsB` / `WithinParams` — the size filter behind `Query.MaxParamsB` (the Max size knob in the Browse page's Filters menu, 120B by default). A **name** parser, because the list endpoint returns no parameter count and the real number is in a GGUF header we'd have to download the model to read. Two rules: the **first** size token wins (a MoE is named `…-235B-A22B`, total then active — taking the last would read a 235B model as 22B, the exact mistake the filter exists to prevent), and an unparseable name is **unknown, so it is kept** — hiding a repo because its author skipped the convention is worse than showing one whose own file sizes will say it's too big. `capParams` in `hf.go` applies it to the response and the search **over-fetches 3x** first, since HF has no size filter of its own and a capped page would otherwise come back nearly empty. The cache stores what the hub said, unfiltered, so a capped search can't poison an uncapped one.
- `Page` / `Query.Skip` — search is **paged, not capped**: the browser loads more as the list is scrolled, so `Search` returns `{Models, NextSkip, HasMore}` and the caller pages by `NextSkip`. That number counts the **hub's own rows**, not the surviving ones — the adapter over-fetches and then filters (size cap, age), so advancing by `len(Models)` would re-request rows already shown or skip rows never shown. `hfPage` deliberately does **not** trim to `Limit` for the same reason: everything that survived the caps is returned, and `Limit` is only how much is asked of the hub. `HasMore` is short-page detection against what was actually fetched. HF's own `skip=` is stable enough to page with, but not enough to guarantee no overlap, so the UI dedups by id.
- `Query.MaxAgeDays` / `capAge` (`hf.go`) — the **Trendy** filter (on by default in the browser): keep only repos **created** within N days, which paired with the existing sort is "popular releases that are new". Judged on `Model.Created`, never `Updated` — `lastModified` moves for a README fix, so a two-year-old repo touched yesterday would read as a new release. A repo stating no creation date is KEPT, same posture as `MaxParamsB`. Applied client-of-the-hub-side for the same reason the size cap is: HF has no created-after filter, which is also why `MaxAgeDays` joins `MaxParamsB` in triggering the 3x over-fetch. **`createdAt` is not in the plain listing** — it takes `expand[]`, which is opt-in *per field* (asking for one drops all the others), so `hfExpand` has to name every field `Model` carries.
- `searchFilters` (`hf.go`) — maps `Query.Kind` (the Browse page's category tab, ids taken from the UI's own `MODEL_CATEGORIES`) onto HF filter tags. The API **repeats and ANDs `filter`**, so each category is `gguf` + a pipeline tag (`text-to-image`, `text-to-speech`, `automatic-speech-recognition`, `feature-extraction`, and `mask-generation` for segment — that, not `image-segmentation`, is what the SAM/BiRefNet GGUF repos carry). `""`/`llm` is plain `gguf`, `any` drops the filter entirely, anything else is passed through as a raw tag. Narrowing at the hub rather than locally is the whole point: a 30-row page filtered client-side would render most tabs empty. The filters are part of the cache key, since they are part of the encoded query.
- `AvatarSource` — an **optional** extra a `Source` may implement (`Avatar(ctx, author) (string, error)`), type-asserted in `handleAPIHubAvatar`. Kept out of `Source` on purpose: it is decoration, and a row without a picture falls back to a monogram. HF needs two lookups because it has orgs and users in one namespace with no endpoint covering both (`/api/organizations/{x}/avatar`, then `/api/users/{x}/avatar`) — and a **miss is cached like a hit**, or a namespace that is neither is asked twice for every row of every search.
- `classify` — turns a repo path into `Shard`/`Shards` + `Group` + `Projector`. **`Group` is load-bearing:** every shard of a multi-part GGUF shares one group key, which is what makes N files one logical download — and since the picker labels a row by its group's base name, that key doubles as the row's displayed name (the shared filename minus `-00001-of-00003`).
- **There is no quant parser, deliberately.** `File.Quant` and `quantRe` are gone; the picker pastes each file's whole name instead. Isolating the tag was shorter but wrong twice over: a miss was *silent* (a recipe marker or suffix the pattern didn't know mislabelled the row rather than failing), and two different files could reduce to the same tag — `mmproj-F16.gguf` rendered as a bare "F16", indistinguishable from the model's own F16 weights. The authority for what a file is has always been the GGUF header, which autogen reads once the file is on disk.
- `Projector` — an mmproj companion, matched by `projectorRe` (`mmproj`/`mm_proj`/`mm-proj` anywhere in the base name; publishers write it both as a prefix and as a `.mmproj.` infix). The whole filename now says so on its own, so the flag exists for the other three behaviours: the **badge**, sorting projectors **below** the models (as the smallest file in a repo it otherwise sorted first, where it read as the cheap option), and showing **"companion"** in place of a VRAM verdict — a projector is charged on top of whichever file you pick, so sizing it alone answers the wrong question.

## Gotchas / conventions

- **`internal/backends.download()` is NOT reused, on purpose.** It `os.Create`s and streams with no resume — fine for a 200 MB backend zip, useless for a 40 GB quant on a flaky line. This package re-implements the transfer with `Range` resume, retry with backoff, cancel, a free-disk precheck, a `.part` file and an atomic rename. The *job/phase/progress vocabulary* is deliberately mirrored from that package so the two managers read the same way.
- **The path is user-chosen; the host must not be.** `CheckURL` pins to `huggingface.co` / `*.hf.co` / `*.huggingface.co` over https only, and it is re-applied **on every redirect hop** (`CheckRedirect`) — a `/resolve/` request is answered with a CDN redirect, so checking only the initial URL would check the one URL that was never going to fetch the bytes. Same posture as `validAssetURL` in `internal/backends`.
- **Two validators, both before anything is used as a URL or a filename.** `validRepoID` (owner/name, hub-legal chars only) and `validRepoPath` (no absolute, no `..`, no backslash, no empty segment). `Start` additionally refuses any file **not present in the hub's own listing** — which both blocks a crafted path and guarantees every job file has a size, the denominator the disk check and the progress bar need.
- **A `.part` file is never renamed into place until the transfer succeeds.** Model discovery walks the models folder; a half-file with a `.gguf` name would be published as a model and fail at load.
- **Pause keeps the bytes; cancel discards them.** They were one operation and it could only be one of the two. `Pause` stops the transfer and leaves every `.part` where it is (`paused` is a **non-terminal** phase — the job stays in the list and `Resume` re-launches it under the same id). `Cancel` deletes the job's partials **and any file this job itself completed**, then the (now empty) repo dir and its owner dir. Finishing one shard of a multi-part GGUF and leaving it behind publishes a broken model into the catalog, which is why cancel takes the whole set — but a `Skipped` file (already on disk before the job started) is never touched, since the job did not put it there. That difference is also what earns the UI's confirmation dialog.
- **A running job's files are deleted by `run()`, not by `Cancel`.** `Cancel` only records the intent (`stop[id]`) and cancels the context; the goroutine's `stopped()` does the removal once it has released the file handle. Windows refuses to delete an open file, so deleting from the caller's side would half-work and leave the `.part` behind.
- **Orphan sweep, age-gated.** `SweepPartials(root, maxAge, log)` walks the models tree and removes `.part` files not touched for `maxAge` (`hubPartialMaxAge`, 14 days, in `internal/server/hubapi.go`), run in the background at startup. The age gate is the point: a `.part` is resumable, so deleting a fresh one throws away real work — only a `.part` nothing has resumed in two weeks is garbage.
- **A 401/403 is terminal, not retryable.** `fetchFile` breaks out of the retry loop on an `AuthError`, because retrying a license wall five times only delays telling the user to accept the license on the model page. The HTTP layer maps it to 403 with that wording.
- **The stall watchdog is not optional.** A TCP connection that goes quiet without erroring would hang the job forever, and "downloading, 41%" frozen for six hours is the worst failure mode this package has. `fetchOnce` cancels its own attempt after `stallTimeout` (2 min) of no bytes; the retry loop then resumes from the `.part`.
- **No client timeout.** A 40 GB file legitimately takes hours. What bounds a hung transfer is the per-attempt context, `ResponseHeaderTimeout`, and the watchdog — never `http.Client.Timeout`.
- **One job per repo, several repos in parallel; files within a job are sequential.** Three concurrent 20 GB pulls on one line finish no sooner and make every progress bar useless.
- **A second pick for a busy repo is QUEUED, not refused.** It used to be an error, which was wrong about the common case: two quants of one repo, or a model plus its projector, are the ordinary reason to click twice, and "come back in forty minutes and click again" is not an answer. `Manager.wait` is the admission FIFO (jobs sitting in `PhaseQueued`), and `pumpLocked` — called from the job goroutine's own defer, the only place a queued job is ever launched — starts whatever the freed repo was blocking. `Resume` admits the same way, so resuming into a busy repo queues rather than failing. `Cancel` on a still-queued job drops it from the queue and **discards nothing**: a `.part` under that repo belongs to whatever is running or paused there, not to a job that never opened a file. `Pause` on one parks it in `PhasePaused` for the same reason `Resume` is the single restart verb. Membership in `wait` (`dequeueLocked`), never `Phase == PhaseQueued`, is what tells a waiting job from a launched one — a launched job is briefly `queued` too, and canceling *that* one from the queue path would leave a live transfer behind a canceled row.
- **`ModelsRoot` is a func, resolved per call.** It is a config value a live reload can change, and a stale root would drop a 40 GB download in the wrong place.
- **The job goroutine recovers its own panics.** `launchLocked` wraps `run` in a `recover()` that logs the stack and lands the job in `error`. A bare goroutine has nothing above it that recovers — unlike an HTTP handler, where `net/http` turns a panic into a dropped connection — so a bug anywhere in the transfer, and especially in `OnComplete` (which regenerates the config and hot-reloads over a models tree that just changed), would take the whole process down at the exact moment a 40 GB download landed. The same code reached from a request survives as a 500; reached from here it killed quartermaster. Note this catches *panics only* — a `fatal error:` (concurrent map write, OOM) is still unrecoverable by design.
- **`OnComplete` failure does not fail the job.** The files *are* on disk; only the config refresh failed. The job ends `done` with an explanatory `Err`, because reporting `error` invites the user to re-download 40 GB that is already there.
- **Progress callbacks are throttled to 1 MiB.** Each one takes the manager lock.

## Not built yet (Feature 11 remainder)

- **A stored, UI-editable token.** `hubToken` (`internal/server/hubapi.go`) reads `HF_TOKEN` / `HUGGING_FACE_HUB_TOKEN` / `HUGGINGFACE_TOKEN` from the environment. The sidecar is the natural home for a managed one.
- **ModelScope adapter.** Mostly a CN mirror, so it earns its keep only for users HF is blocked for.
- **Image-model sibling sets.** A diffusion repo needs its vae/clip/encoder files together in the layout autogen expects; today the picker groups GGUF shards but does not know those sibling relationships.

## Connections

Depends on: `github.com/shirou/gopsutil/v4/disk` (free-space precheck) and the standard library only — deliberately no dependency on `internal/autogen`, so the downloader stays testable without a models tree.

Called by: `internal/server/hubapi.go` (the admin-gated `/api/hub/*` routes) — which supplies `ModelsRoot` from the autogen settings and wires `OnComplete` to `regenReload`.
